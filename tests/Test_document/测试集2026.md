# TaskMonitor 测试集

本测试集围绕 TaskMonitor 的核心任务闭环进行设计，主要验证系统从任务意图接入、任务状态机创建、子任务流程推进，到用户查询、人工干预和二次确认的完整能力。

## 测试说明

### 输入方式

1. **后端信息输入方式**：在运行系统主程序之外，新建一个终端用于输入后端状态信息，即 `curl` 命令。
2. **前端信息输入方式**：在系统主程序运行后，通过网页聊天窗口输入对应问题或人工干预指令。

---

## 任务创建

**测试目标**：验证任务意图书扫描、任务状态创建、S1-S8 子任务生成功能是否正常。

- 新建新的任务意图书：在 ./tasks 中上传需要处理任务意图 JSON 文件
- 运行：

1. **启动系统**

```markdown
python run.py
```

2. **放置任务文件**

```bash
cp task_intent_TI2026021192.json task/
```

3. **确认任务已创建**

```bash
curl --noproxy '*' -s http://localhost:8889/api/tasks
```

## 判据失败测试

**测试目标**：验证硬判据或软判据不满足时，系统的状态变化、后端返回和可恢复方式。

### TS1: 子任务硬判据不满足，软判据满足/不满足

- 以 S1 子任务为例，验证硬判据不满足时，系统反应及对应可行处理操作。
- **后端输入**：

```bash
curl --noproxy '*' -X POST http://localhost:8889/api/task/update -H "Content-Type: application/json" -d '{"task_id":"TI2026021192","type":"status_update","data":{"subtask_id":"S1","status":"reported","criteria_details":{"distance_error_m":0.15,"angle_error_deg":5.0,"speed_stable_frames":5,"grid_count":15,"panel_visible_flag":1,"plug_stable_flag":1},"anomaly_state":{"data_commun":"normal","perception":"normal","planning":"normal","execution":"normal","plant":"normal"}}}'
```

- **后端期望输出**：

```markdown
{"action":"fail_task","subtask_id":"S1"}
```

- **期望模型输出 / 前端表现**：

```markdown
<状态栏>：由于硬判据"distance_error_m":0.15 > 0.1, 对应任务的子任务状态栏变为失败状态，此时无法在后端上报任何外部状态数据
<模型输出>: 无输出
```

- **解决方案**：
  - 通过对话栏进行人工干预操作,

    - 重试当前任务后将当前子任务状态变为执行中，此时可重新上报正确参数重新进行审核

    ```markdown
    用户：重试当前任务 -> 系统生成干预确认审核通知 -> 用户：确认 -> 状态更新为执行中 -> 重新上报外部状态数据
    ```

    - 修改准入条件，修改判据准入数值使得此时外部状态数据满足条件

    ```markdown
    用户：把距离误差改成0.15米 -> 系统生成干预确认审核通知 -> 用户：确认 -> 重新进行状态审核 -> 状态更新
    ```

    - 覆盖外部状态数据解决，将外部状态数据覆盖新值满足判据条件

    ```markdown
    用户：把实际距离误差改成0.05米 -> 系统生成干预确认审核通知 -> 用户：确认 -> 重新进行状态审核 -> 状态更新
    ```

### TS2: 子任务硬判据均满足，软判据不满足

- 以 S1 子任务为例，验证软判据不满足时，系统反应及对应可行处理操作。
- **后端输入**：

```bash
curl --noproxy '*' -X POST http://localhost:8889/api/task/update -H "Content-Type: application/json" -d '{"task_id":"TI2026021192","type":"status_update","data":{"subtask_id":"S1","status":"reported","criteria_details":{"distance_error_m":0.05,"angle_error_deg":5.0,"speed_stable_frames":5,"grid_count":9,"panel_visible_flag":1,"plug_stable_flag":1},"anomaly_state":{"data_commun":"normal","perception":"normal","planning":"normal","execution":"normal","plant":"normal"}}}'
```

- **后端期望输出**：

```markdown
{"message":"subtask still in progress","ok":true}
```

- **期望模型输出 / 前端表现**：

```markdown
<状态栏>：由于软判据 grid_count=9 < 10 不满足条件，此时子任务状态仍然是执行中，可随时上报正确外部状态数据此时无法在后端上报任何外部状态数据
<模型输出>: 无输出
```

- **解决方案**：
  - 由于此时仍然处于执行状态，此时可直接在后端输入新的外部状态数据进行审核
    ```bash
    curl --noproxy '*' -X POST http://localhost:8889/api/task/update -H "Content-Type: application/json" -d '{"task_id":"TI2026021192","type":"status_update","data":{"subtask_id":"S1","status":"reported","criteria_details":{"distance_error_m":0.05,"angle_error_deg":5.0,"speed_stable_frames":5,"grid_count":15,"panel_visible_flag":1,"plug_stable_flag":1},"anomaly_state":{"data_commun":"normal","perception":"normal","planning":"normal","execution":"normal","plant":"normal"}}}'
    ```

## 查询问答测试

**测试目标**：验证任务进度、失败原因、判据详情、异常信息、干预生效情况、任务书基础信息和无关问题识别。

### TS1: 查询任务进度

- **用户输入**

```markdown
当前任务状态如何呢？
```

- **期望模型输出**：说明当前任务处于失败状态，指出当前失败子任务为 S1，并说明主要原因是距离误差超过允许阈值，同时给出可执行建议。
- 期望模型输出示例

```markdown
任务 TI2026021192 当前处于失败状态。
```

## 人工干预确认测试

**测试目标**：验证 `retry`、`rollback`、`change_parameter`、`override_field`、`force_complete` 等人工干预请求的识别、二次确认和执行结果。

**用例格式**：本节用例均采用多轮对话表格，格式为“轮次 / 角色 / 内容”。第一轮验证系统能否解析干预意图并生成确认请求；第二轮验证用户确认后系统能否执行对应动作。

### TS1: retry

- **对话内容**

| 轮次 | 角色              | 内容                                                                                                                                                                                                |
| ---- | ----------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | user              | 重试 S1                                                                                                                                                                                             |
| 1    | assistant（预期） | 已收到您的重试指令。系统将重新执行子任务 S1“移动至采油树控制面板附近”。此次重试会重置 S1 的运行状态，并重新收集位置偏差、稳定性等判据数据。请回复“确认”以执行重试，或回复“取消”以终止该操作。 |
| 2    | user              | 确认                                                                                                                                                                                                |
| 2    | assistant（预期） | 已确认执行重试。子任务 S1 已重新进入执行中状态，任务整体恢复为`in_progress`。请重新上报 S1 的状态数据。                                                                                           |

- **期望模型解析出的结构化动作**：

```json
{"action":"retry","subtask_id":"S1"}
```

- **期望执行效果**：
  - 当当前子任务等于重试目标子任务时，可执行重试动作。
  - 执行重试后，目标子任务状态信息被重置，可重新发起执行。
  - 当当前子任务不等于重试目标子任务时，不可直接执行重试动作。
